# stats-init · 统计学科研项目初始化

初始化时只做一件事：在项目根目录铺好固定的目录与记录文件骨架；除 `command.md` 直接写入完整指南外，具体内容留到后续填充。各记录文件的追加 / 同步规则见下文。

## 命令

```text
/stats-init [项目根目录]
/stats-init [项目根目录] --dry-run
```

- 不写参数：使用当前工作目录。**先确认它就是项目根目录**；若当前在子目录，把根目录作为参数传入，不要靠猜。
- `--dry-run`：只列出将新建的项，不写磁盘。
- 目录或文件已存在：保留原样，不覆盖、不合并；在回复里点名哪些是保留项。

## 执行步骤

1. 解析目标根目录；目录不存在时脚本会创建。
2. 运行脚本（`<skill目录>` 是本 `SKILL.md` 所在目录，路径含空格时加引号）：

   ```bash
   node "<skill目录>/scripts/init.mjs" "<项目根目录>"
   ```

3. 读脚本输出：只有标为“新建”的项是本次改动；“保留”的项说明项目里已有，不要动。
4. 回复用户：
   - 用一个代码块给出文件树；
   - 一句话写明新建 / 保留的数量；
   - 一句话说明 `command.md` 已写入完整指南，后续 agent 先读它；
   - 一句话给出下一步（先填 `idea.md` 与 `notation.md`，或问是否现在填充）。
5. `command.md` 由脚本直接写入完整指南；其余文件只建骨架。用户当场要求填充时，才按下面的“各文件用途”写正文。

## 生成的骨架

```text
<项目根>/
├── code/          # 分析代码、模拟、可复现脚本；文件用 01_ 前缀
├── result/        # 图表、表格、数值结果等产出；文件用 01_ 前缀
├── doc/           # 论文、笔记、推导、审稿材料；文件用 01_ 前缀
├── materials/     # 外部获取的文献、数据；保留原名，不编号
├── idea.md        # 想法：主灵感（M）/ 次灵感（L），段尾追加
├── notation.md    # 记号表：四类分节，四列（符号/含义/宏键/出处）
├── main_log.md    # 主日志：节点操作，时间 | 操作 | 产出/结果
├── index.md       # 文件索引：按目录分节，路径/作用/性质
├── thm_index.md   # 定理索引：定理/内容/陈述位置/证明位置
└── command.md     # 给 agent 的项目使用指南
```

文件名固定为小写加下划线（`main_log`、`thm_index`），不要改成 `main-log` 或大写。脚本是幂等的，重复执行只会补齐缺失项。

## 各文件用途

| 文件 | 最少要写什么 |
|---|---|
| `idea.md` | 只记未成熟 / 未形式化想法：`# 主灵感（M）` 与 `# 次灵感（L）` 两段，条目追加到段尾；格式见下节。 |
| `notation.md` | 四节（集合 / 随机变量 / 参数 / 算子）各一张表，四列固定：符号 / 含义 / 宏键 / 出处；规则见下节。 |
| `main_log.md` | 节点操作日志：每行“时间、操作、产出/结果”三字段；只记实际执行，不记计划；修订并入首条。 |
| `index.md` | 文件索引：按 code / result / doc / materials 分节，每节一张表（路径 / 作用 / 性质）；新建、改名、删除文件时同步。 |
| `thm_index.md` | 定理与命题索引：定理 / 定理内容 / 所在位置 / 证明所在位置；只记陈述与位置，不抄证明。 |
| `command.md` | 给 agent 的项目使用指南：目录、先读什么、各记录文件的同步规则、工作流、完成前检查、约定、常用命令。 |

## 目录内命名

`code/`、`result/`、`doc/` 下的第一层文件和子目录用两位编号前缀：`01_`、`02_`……，每个目录独立递增。编号按首次创建分配，取该目录当前最大编号 +1；不复用、不重排，插入内容时用新号。

```text
code/01_sim_bh.py
result/01_fdr_by_m.csv
doc/01_main.tex
doc/02_intro.tex
```

`materials/` 放从外部获取的文献、数据、代码，保留原名，不编号（如 `BenjaminiHochberg1995.pdf`）；在 `index.md` 的作用列写清来源。子目录内部另起序列。

## idea.md 记录规则

`idea.md` 只收未成熟或未形式化的想法，不是论文正文。文件固定两段，顺序不变：

1. `# 主灵感（M）`：可能支撑一篇论文或一个方法的核心想法。
2. `# 次灵感（L）`：局部观察、小改进、待验证的旁支。

新条目一律追加到对应段的**末尾**（M 段末尾在 `# 次灵感（L）` 之前，L 段末尾即文件末尾）；不插队、不按日期重排、不跨段搬移。

条目形式固定：

```markdown
## YYYY-MM-DD | M-01
- 短灵感：一句话。
- 扩展说明：动机；形式化表述；可能的方法 / 定理；验证方式；风险。
- 状态：待验证
```

- **日期**：默认记录当天日期；用户明确给出日期时用给出的日期。
- **编号**：`M-01`、`M-02`……与 `L-01`、`L-02`……；按段独立递增，只增不减、不复用（条目被否证也不回收）。空段从 `01` 开始；新增前读该段最后一个编号，再 +1。
- **短灵感**：一句话，写成可检验的猜想或明确做法（如“若……则……”），不写领域综述。
- **扩展说明**：一条内按“动机；形式化表述；可能的方法 / 定理；验证方式；风险”写；没想清的部分写“待定”，不编造定理、文献或实验。
- **状态**：只能是 `待验证` / `进行中` / `已否证` / `已成文`；新条目默认 `待验证`。
- **更新**：状态可原地改，只动该条目的 `- 状态：` 行；标题、其他字段和条目位置都不动。其余字段只在用户明确要求修订时改。
- **校验**：写入前确认标题匹配 `^## \d{4}-\d{2}-\d{2} \| [ML]-\d{2,}$`、三个 bullet 齐全、状态合法、编号在该段唯一；不满足就停，先报告缺哪一项。
- 同一段内按记录顺序排列，不按日期排序；同一天多条按编号递增。

用户只说“记一个想法”时：先判断 M 还是 L，判断不了只问这一个问题。文件缺少上述两段时不要自行重建，先报告并问是否迁移。写入后只回报编号与所在段，不复述全文。

## notation.md 记录规则

`notation.md` 是项目实际使用的符号清单。一个符号在推导、代码或文档中确定使用后，就在同一轮登记到对应表末尾；未定的草稿符号先不登记。

### 表结构

四列固定，不增不减。示例：

```markdown
| 符号 | 含义 | 宏键 | 出处 |
| --- | --- | --- | --- |
| $\mathbf{W}$ | $m$ 维竞争分数向量 | `\bW` | `doc/01_main.tex L12` |
| $\alpha$ | 名义 FDR 水平，$\alpha\in(0,1)$ | — | `预设` |
```

- **符号**：`$...$` 包住的完整 LaTeX 命令；本文件与 Markdown 正文都不写 `\bW`、`\cR` 这类简写。
- **含义**：只写定义本体（量词、定义域、结构），保证无歧义；定理陈述、收敛性质、适用条件等论证性内容不写。
- **宏键**：`.tex` 源中的简写宏名，如 `\bW`；无宏的常用记号（`\alpha`、`n`）填 `—`。先查 `stats-tex-macros` 的对照表：已有的宏直接填；相对于它新增的宏只在本项目使用，宏键照填，并在文末「新增宏定义」用 `latex` 代码块写 `\newcommand`，一行一个，不重复已有宏。
- **出处**：该记号首次出现的文件位置（相对项目根，写作 `文件 L行`）；在预设中定义的填 `预设`。

长定义：Markdown 表格内放不下独立公式块，统一放在该表下方，按行序用 `$$ ... \tag{N1} $$` 展开；全文连续编号 `(N1)`、`(N2)`…，单元格写“一句话，见式 (N1)”。

### 分节

固定四节，顺序不变；每节一张表，新行追加到该表末尾，不按字母或日期重排。

1. **集合类**：集合、指标集、事件集、拒绝集等；随机集合也归此类。
2. **随机变量类**：随机变量、随机向量、样本元、统计量、估计量、p 值、数据依赖的阈值等。统计量是随机变量，不要因为“由样本算出”放进参数类。
3. **参数类**：固定未知参数、样本量、假设个数、名义水平等不随样本变化的量。
4. **算子类**：概率、期望、指示、微分、argmax 等算子；渐近记号与关系记号也放这里，避免另开一节。

分节只看数学类型，不看“确定性 / 数据依赖”：$\mathcal{R}$ 即使随机，仍是集合；$T$ 即使数据依赖，仍是随机变量。

### 冲突与更新

- 与预设 / 通用记号约定冲突时，以本文件为准；在对应表下方加一行 `> 备注：<改动了哪一处>`，不新增第五列。
- 同一符号只占一行；含义变化时改原行并加备注，不追加重复行。
- 新符号追加到对应表末尾；顺序按首次登记，不重排。

## main_log.md 记录规则

只记已经发生并产生结果的节点操作，不记计划、待办、下一步。节点完成或失败后再记；进行中的操作不记。

格式固定为一行，三个字段用 ` | ` 分隔：

```text
YYYY-MM-DD HH:MM | 操作 | 产出/结果
```

- **时间**：本地时间，24 小时制，补零；取节点完成时刻。不猜测、不回填。
- **操作**：动词开头，写清对象和范围（如 `运行 BH 模拟（m=1000，1000 次重复）`）；不写“准备”“计划”。
- **产出/结果**：具体可验收。有文件写相对路径；有数值写关键数值；只有结论写一句话；失败写 `失败：原因`。不写“完成”“见结果”这类空话。
- 字段内不出现 `|`；并列内容用 `；`。一条只记一个节点。
- 按时间升序追加到文件末尾；条目之间空一行，避免 Markdown 渲染时粘连。

什么算节点：初始化、目录 / 文件结构变更、跑完一组实验或模拟、完成或推翻一个证明、生成图表或表格、完成论文一节或一稿、做出影响后续路线的决定、投稿 / 修回。日常阅读、搜索、格式调整、反复调试不单独记。

同一事件的后续修订（重跑、补证、改图、润色）并入首条：只更新首条的 `产出/结果`，保留首次时间，不新增行。换了目标、对象或产出物才是新事件；同一产出的结果被修正仍算修订。合并前确认是同一目标 / 同一产出；不确定就问，不要硬并。

## index.md 记录规则

`index.md` 是当前内容文件的索引，不是历史日志；历史操作记在 `main_log.md`。只索引 `code/`、`result/`、`doc/`、`materials/` 下的长期文件；根目录六个记录文件、临时文件、缓存、编译中间产物（`.aux`、`.log`、`.out`、`.toc`、`.synctex.gz`）不索引。

按顶层目录分节，每节一张表，三列固定：

| 路径 | 作用 | 性质 |
| --- | --- | --- |
| `code/01_sim_bh.py` | BH 过程的蒙特卡洛模拟 | 入口 |

- **路径**：相对项目根，用反引号包住；`code/`、`result/`、`doc/` 下的文件带 `01_` 前缀，`materials/` 保留原名。
- **作用**：一句话说明文件做什么、产出什么；有关联写 `对应 M-01 / 定理 3.1`。
- **性质**：`入口`（可直接运行）/ `源文件`（手改）/ `生成物`（脚本或编译产出，不手改）/ `数据` / `文档`（只读参考）。

同步规则：新建文件 → 在对应节加一行；改名或移动 → 改路径（必要时换节）；删除 → 删行；作用或性质变化 → 改对应字段。都在同一轮完成，不攒到最后。同一节内按首次登记顺序追加，不重排。新增顶层目录时加一节；空目录不列。

## thm_index.md 记录规则

`thm_index.md` 只索引定理与命题，方便定位；不抄证明，也不替代正文。四列固定：

| 定理 | 定理内容 | 所在位置 | 证明所在位置 |
| --- | --- | --- | --- |
| `定理 3.1（thm:bh）` | 若 $p$ 值满足 PRDS，则 BH 过程在水平 $\alpha$ 下控制 $\mathrm{FDR}\le\alpha$ | `doc/01_main.tex L120–L128` | `doc/01_main.tex L130–L160` |

- **定理**：类型 + 编号；有名字或 `\label` 可括注。定理、命题都要标类型，不混写。
- **定理内容**：条件 + 结论的完整陈述；公式用 `$...$`；不写证明。过长时可压缩措辞，但条件与结论不能省。集合竖线用 `\mid`，不要在单元格里写裸 `|`。
- **所在位置**：定理陈述所在的文件与行范围，写作 `文件 L起–L止`。
- **证明所在位置**：证明所在的文件与行范围；新建时证明还没写填 `待补`；确定不证或引用现成结论填 `—`；证明在附录就指向附录。

同步规则：新建定理 / 命题 → 加一行；修改陈述 → 改「定理内容」与「所在位置」；补证明 → 填「证明所在位置」；编号变化 → 改「定理」列，不新增行；删除 → 删行。都在同一轮完成。按首次登记顺序追加，不重排。

默认只收定理与命题；引理、推论如果要进索引，按同格式加一行，类型照写。

## command.md 指南

`command.md` 是给在这个项目里工作的 agent 看的操作手册，初始化时直接写入完整内容，不留空。它覆盖：目录与文件职责、开始任务前先读什么、五个记录文件的同步规则、常见任务的工作流、完成前检查、约定、常用命令表。

项目里新增固定命令或改变操作约定时，同步改 `command.md`。它和本 skill 的通用规则冲突时，以项目里的 `command.md` 为准（项目特有约定优先）。改本 skill 的通用规则时，同步改 `templates/command.md`，否则新项目拿到的指南会过期。

## 约束

- 只创建缺失项；不覆盖、不删除、不移动任何已有内容。
- 初始化阶段不写研究内容，也不编造问题、符号或定理；用户明确要求填充时才写。
- 不添加用户没要求的文件或目录（`README.md`、`.gitignore`、`data/`、`figures/` 等都不加）。
- 不在初始化时运行分析代码、生成结果或改动 git 状态。
- 脚本失败（权限不足、目标路径是文件等）时原样报错，不手工绕过或换路径重试。

## 资源

- `scripts/init.mjs` — 幂等脚手架脚本，只依赖 Node 标准库。
- `templates/command.md` — 初始化时写入项目的 agent 使用指南。

插件包只带以上运行文件；示例与冒烟测试不随插件分发。
