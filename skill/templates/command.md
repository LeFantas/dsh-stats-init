# 项目使用指南（给 agent）

本项目按固定结构记录统计学科研过程。开始任务前先读本文件，再按需读 `index.md`、`notation.md`、`thm_index.md`、`main_log.md`、`idea.md`。

## 目录与文件

```text
code/         分析代码、模拟、可复现脚本（文件用 01_ 前缀）
result/       图表、表格、数值结果等产出（文件用 01_ 前缀）
doc/          论文、笔记、推导、审稿材料（文件用 01_ 前缀）
materials/    外部获取的文献、数据、代码（保留原名，不编号）
idea.md       想法：主灵感（M）/ 次灵感（L）
notation.md   符号表：四类分节，四列（符号 / 含义 / 宏键 / 出处）
main_log.md   节点操作日志
index.md      文件索引
thm_index.md  定理与命题索引
command.md    本文件
```

## 命名

- `code/`、`result/`、`doc/` 下的第一层文件和子目录用 `01_`、`02_`…… 前缀，每个目录独立递增。
- 编号按首次创建分配，取该目录当前最大编号 +1；不复用、不重排。
- `materials/` 保留外部原名，不编号；在 `index.md` 里写清来源。

## 开始任务前

1. 读本文件。
2. 读 `index.md`，确认相关文件的位置与现状。
3. 需要符号查 `notation.md`；需要定理查 `thm_index.md`；需要历史查 `main_log.md` 最近几条。
4. 沿用现有目录与命名；不要新建平行结构。

## 记录文件怎么同步

### idea.md

- 只记未成熟 / 未形式化想法，分 `# 主灵感（M）`、`# 次灵感（L）` 两段。M 是可能支撑论文 / 方法的核心想法；L 是局部观察、小改进、待验证旁支。
- 新条目追加到对应段末尾；编号从 `M-01` / `L-01` 起，按段递增，不复用。
- 条目格式：

```markdown
## YYYY-MM-DD | M-01
- 短灵感：一句话。
- 扩展说明：动机；形式化表述；可能的方法 / 定理；验证方式；风险。
- 状态：待验证
```

- 状态只能 `待验证 / 进行中 / 已否证 / 已成文`；状态可原地改，其余字段和位置不动。

### notation.md

- 四节：集合类、随机变量类、参数类、算子类；每节一张表。
- 分节只看数学类型：随机集合归集合类；统计量、p 值、数据依赖阈值归随机变量类；参数类只放固定量；算子类兼放渐近与关系记号。
- 四列：`符号 | 含义 | 宏键 | 出处`。
- 符号用 `$...$` 包住完整 LaTeX；Markdown 中不写 `\bW`、`\cR` 这类简写。
- 含义只写定义本体；长定义放表下 `(N1)` 公式块，单元格写“见式 (N1)”。
- 宏键写 `.tex` 简写；无宏填 `—`；新增宏在文末 `## 新增宏定义` 写 `\newcommand`。
- 出处写 `预设` 或 `文件 L行`；冲突在表下写 `> 备注：...`，不加第五列。
- 新符号确定使用后立即登记；同一符号只一行。

### main_log.md

- 只记实际执行并产生结果的节点操作，不记计划。
- 节点示例：初始化、结构变更、跑完实验、完成 / 推翻证明、生成图表、完成一节 / 一稿、关键决定、投稿 / 修回；日常阅读与格式调整不记。
- 每行：`YYYY-MM-DD HH:MM | 操作 | 产出/结果`；条目之间空一行。
- 同一事件的重跑、补证、改图、润色并入首条，只更新结果，保留首次时间。

### index.md

- 按 `code/`、`result/`、`doc/`、`materials/` 分节，每节一张表：`路径 | 作用 | 性质`。
- 性质：`入口 / 源文件 / 生成物 / 数据 / 文档`。
- 新建、改名、移动、删除文件时同步更新；不索引根目录记录文件、临时文件、编译中间产物。

### thm_index.md

- 只索引定理与命题；引理、推论要进索引时按同格式加，类型写清。
- 四列：`定理 | 定理内容 | 所在位置 | 证明所在位置`。
- 定理列写类型 + 编号；内容写条件 + 结论，不抄证明；位置写 `文件 L起–L止`。
- 证明未写填 `待补`，不证填 `—`；新建、改陈述、补证明、改编号、删除时同步。

## 工作流

- 新建内容文件：放进对应目录 → 更新 `index.md` → 若是节点操作，更新 `main_log.md`。
- 确定新符号：更新 `notation.md` 对应表 → 如需新宏，写文末定义。
- 新建定理 / 命题：写入正文 → 更新 `thm_index.md`。
- 记录想法：按 M / L 追加到 `idea.md`。
- 完成一组实验 / 证明 / 稿件：更新 `main_log.md`；有产出文件再更新 `index.md`。

## 完成前检查

- 新建 / 改名 / 删除文件 → `index.md` 同步了吗？
- 新符号 → `notation.md` 登记了吗？
- 新定理 / 命题 → `thm_index.md` 登记了吗？
- 节点操作 → `main_log.md` 记了吗？
- 新想法 → `idea.md` 追加了吗？

## 约定

- 路径相对项目根。
- Markdown 与 `notation.md` 用完整 LaTeX；`\bW`、`\cR` 等简写只出现在 `.tex` 源和 `notation.md` 的宏键列。
- 不覆盖已有条目；文件 / 定理删除时按索引规则删对应行，历史留在 `main_log.md`。
- 不把证明抄进 `thm_index.md`，不把计划写进 `main_log.md`。
- 文件名固定：`main_log.md`、`thm_index.md`，不要改大小写或连字符。
